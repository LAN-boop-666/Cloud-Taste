# 云味餐厅环境运行指南

这份指南用于按黑马《苍穹外卖》课程的本地结构运行云味餐厅。微信小程序不纳入本项目环境。

## 目录对应关系

| 部分 | 用什么打开 | 项目位置 | 默认地址 |
| --- | --- | --- | --- |
| Java 后端 | IDEA | `D:\workspace\cloud-taste\backend\sky-take-out` | `http://127.0.0.1:8080` |
| 管理端源码 | VS Code | `D:\workspace\cloud-taste\admin-web\project-sky-admin-vue-ts` | `http://127.0.0.1:8889` |
| 管理端打包版 | 浏览器 + Nginx | `D:\workspace\cloud-taste\admin-dist\nginx-1.20.2` | `http://127.0.0.1` |
| 数据库脚本 | MySQL 客户端 | `D:\workspace\cloud-taste\database\cloud_taste.sql` | MySQL `3306` |
| 项目脚本 | PowerShell | `D:\workspace\cloud-taste\scripts` | - |

## 环境现状

- Java `17.0.10` 已验证。
- Maven 使用后端自带 Wrapper `3.9.6`，不要求全局 `mvn`。
- MySQL 服务 `MySQL80` 已运行，数据库 `cloud_taste` 已导入 11 张表。
- 项目内置 Node `12.22.0`，位置为 `D:\workspace\cloud-taste\.tools\node-v12.22.0\nodejs`。
- 全局 Node 22 不会被替换。前端脚本只在当前 PowerShell 进程中临时使用 Node 12。
- 前端依赖位于 `admin-web\project-sky-admin-vue-ts\node_modules`，不会提交到 Git。
- 当前 `8888` 被其他本机服务占用，所以源码前端固定使用 `8889`。

## 第一次完整启动

### 1. 数据库

MySQL 服务已经运行。若服务未运行，在 Windows 服务中启动 `MySQL80`。不要猜测或把 MySQL 密码写进项目。

数据库初始化脚本只在数据库不存在时使用：

```powershell
cd D:\workspace\cloud-taste
.\scripts\init-database.ps1
```

数据库已存在时脚本会停止，不会覆盖数据。

### 2. 后端

#### IDEA 打开

1. IDEA 选择 `Open`。
2. 打开 `D:\workspace\cloud-taste\backend\sky-take-out`。
3. Maven 刷新完成后，运行：

```text
sky-server\src\main\java\com\sky\SkyApplication.java
```

将
`D:\workspace\cloud-taste\backend\sky-take-out\sky-server\src\main\resources\application-local.yml.example`
复制为 `application-local.yml`，填写你的 MySQL 密码。该文件已被 Git 忽略。

也可以在 IDEA 的 Run Configuration -> Environment variables 中添加：

```text
CLOUD_TASTE_DB_PASSWORD=你的MySQL密码
```

本机配置文件或 IDEA 运行配置只保存在本机，不要写入 Git 或聊天记录。

#### PowerShell 打开

```powershell
cd D:\workspace\cloud-taste
.\scripts\start-backend.ps1
```

脚本会优先使用本机 `application-local.yml`；如果密码仍为空，才会隐藏提示输入 MySQL 密码。后端端口是 `8080`。

验证：

```text
http://127.0.0.1:8080/doc.html
```

### 3. 管理端打包版 Nginx

这是课程中“前端打包后部署”的运行方式，不需要 Node：

#### 从文件夹打开（与课程一致）

1. 打开 Windows 文件资源管理器。
2. 在地址栏粘贴并回车：

```text
D:\workspace\cloud-taste\admin-dist\nginx-1.20.2
```

3. 双击 `nginx.exe`。Nginx 在后台运行，通常不会出现操作窗口。
4. 在浏览器访问：

```text
http://localhost/
```

如果页面能打开但无法登录，先在 IDEA 中运行后端的
`sky-server\src\main\java\com\sky\SkyApplication.java`。前端页面使用 `80`
端口，后端接口使用 `8080` 端口。

#### 使用 PowerShell 打开

```powershell
cd D:\workspace\cloud-taste
.\scripts\start-nginx.ps1
```

访问：

```text
http://localhost/
```

#### 停止 Nginx

无论采用文件夹还是 PowerShell 启动，都可以执行：

```powershell
cd D:\workspace\cloud-taste
.\scripts\stop-nginx.ps1
```

只有后端也运行时，登录、员工数据和其他接口才会正常。

### 4. 管理端源码开发服务器

#### VS Code 打开

用 VS Code 打开：

```text
D:\workspace\cloud-taste\admin-web\project-sky-admin-vue-ts
```

这个项目是 Vue 2 + Vue CLI 3 + TypeScript。源码修改后会热更新。

#### PowerShell 打开

```powershell
cd D:\workspace\cloud-taste
.\scripts\start-admin-dev.ps1
```

访问：

```text
http://127.0.0.1:8889/
```

脚本使用项目内 Node 12，不会改变全局 Node 22。

如果以后 `8889` 也被占用，可以指定其他端口：

```powershell

```

### 5. 前端依赖重新安装

通常不需要重复安装。只有 `node_modules` 损坏或被清理时才执行：

```powershell
cd D:\workspace\cloud-taste
.\scripts\install-admin-deps.ps1
```

脚本会临时修复课程 lockfile 中过期的镜像下载地址，安装后恢复原始 `package-lock.json`。`CYPRESS_INSTALL_BINARY=0` 只跳过 Cypress 浏览器程序下载，不影响前端页面开发。它用于避免课程老版本测试工具下载超时。

## 停止方式

- IDEA 后端：点击运行窗口的红色停止按钮。
- PowerShell 后端：在运行窗口按 `Ctrl+C`。
- Nginx：执行 `.\scripts\stop-nginx.ps1`。
- Vue CLI：回到运行窗口按 `Ctrl+C`。

## 常见现象

- 页面能打开但登录失败：后端没有启动，或 MySQL 密码未配置。
- Nginx 页面出现接口 `502`：后端 `8080` 没有监听。
- Vue CLI 地址变成其他端口：原端口被占用，使用终端显示的地址。
- npm 报 `CERT_HAS_EXPIRED`：课程锁文件引用了过期镜像；使用上面的项目内 npm 7 安装命令。
- npm 22 安装 `fibers` 失败：不要继续用全局 Node 22，使用项目内 Node 12 脚本。
- Sass、Vue Router 类型错误：依赖没有按 lockfile 安装，重新执行项目内 npm 7 的 `ci` 命令。

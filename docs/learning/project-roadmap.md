# 云味餐厅实施路线

## 目标与边界

云味餐厅以黑马程序员《苍穹外卖》为学习主线。第一阶段保持课程的业务顺序、接口路径、数据库表和 Java 分层结构；AI 负责减少重复劳动、解释原理、补测试、排错和验收，不替代核心业务练习。

课程最终工程仅用于故障定位和完成度核对，不直接覆盖学习工程。

## 里程碑

| 阶段 | 课程内容 | 必须掌握 | 验收结果 |
| --- | --- | --- | --- |
| M0 | Day01 环境搭建 | 多模块、请求链路、Nginx、接口文档 | 后端编译，数据库可用，登录接口通过 |
| M1 | Day02 员工与分类 | DTO、分页、状态变更、异常处理 | 员工和分类接口回归通过 |
| M2 | Day03-Day04 菜品与套餐 | 多表写入、事务、动态 SQL | 菜品和套餐完整 CRUD 通过 |
| M3 | Day05 Redis | 数据类型、营业状态 | Redis 读写和营业状态通过 |
| M4 | Day06-Day07 用户点餐 | 用户身份、缓存、购物车 | 浏览、缓存、购物车链路通过 |
| M5 | Day08-Day10 订单 | 下单事务、状态机、定时任务、WebSocket | 订单主流程和异常流程通过 |
| M6 | Day11-Day12 报表 | 统计 SQL、ECharts、Excel | 统计与导出结果正确 |
| M7 | 原创扩展 | 产品设计、测试、工程化 | 与课程明显区分并完成整体回归 |

## 每章工作方式

1. 先看视频中的需求分析和接口设计，不提前复制实现。
2. 在项目中标记本章范围和验收用例。
3. 核心业务代码由 LAN 跟课理解；重复 DTO、映射、配置和测试样板可由 Codex 协助。
4. 运行编译、接口、数据库和必要的前端验证。
5. 更新 `learning-progress.md`，形成一个可回退的 Git 提交。

## 原创扩展候选

课程主线完成前不实施以下内容，只保留设计入口：

- 门店与多租户隔离
- 优惠券、满减和营销活动
- 菜品库存与售罄管理
- 订单评价和售后流程
- 操作审计日志
- Testcontainers 集成测试
- 管理端 Vue 3、Vite、Pinia 迁移
- Spring Boot 3 升级分支

最终根据学习效果选择 2-4 项，优先保证业务闭环和测试质量，不追求功能数量。

## Git 与发布

- 每个里程碑至少形成一个清晰提交。
- 不提交密码、密钥、本地依赖缓存、构建日志和课程临时导入区。
- `main` 保存可运行阶段，学习中的修改使用阶段分支。
- 推送目标为 `https://github.com/LAN-boop-666/Cloud-Taste.git`。
- 只有构建、核心接口和敏感信息检查通过后才推送阶段成果。
